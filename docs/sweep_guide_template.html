The SWEEP tab

One match tells you what happened once. SWEEP runs hundreds of them at once, varying one or two things about a robot, and lets you see how the score actually responds -- the difference between "I watched it and it seemed faster" and an answer you can defend.

No statistics background assumed. The one idea worth understanding going in: a single match is not a measurement, it's a sample -- and everything about how this tab is built follows from that.

01Why one match isn't enough

Game pieces scatter randomly, robots don't accelerate identically tick to tick, and two otherwise identical robots can win by 12 or lose by 4 depending on nothing meaningful at all. Watch one match with a faster drivetrain, see a higher score, and you've learned almost nothing -- it might be the speed, or it might just be that match's luck.

A sweep answers this by running the same design many times over (repetitions), with randomness turned on (variability) so those repetitions aren't just the same match copy-pasted, and often crossed against a second thing you're curious about -- speed vs. strategy, say -- so you get a whole grid of answers from one run instead of one match at a time.

03The trap: repetitions that all look the same

Read this before you set Repetitions above 1

Repetitions only does something useful if Enable variability is also checked. Without it, nothing in a match actually consumes randomness -- robot characteristics don't perturb, start poses don't shift, pieces don't scatter differently -- so every repetition of the same design point runs the exact same match and produces the exact same score. Ten repetitions of nothing new is ten rows that say the same thing, which looks like data but isn't.

The tab watches for this: if you have Repetitions above 1 with variability off, an amber warning appears under the run controls. Turn variability on before you trust a spread of repeated scores to mean anything.

04Walkthrough: the results table

One row per match, filled in live as the sweep runs: the variable values it used, its final score, and a few other metrics. A row in red means that particular match crashed -- hover it for the error.

07When something looks wrong

SymptomWhat is going on
Every repetition of a point has the identical score Enable variability is off. See "The trap" above.
EXECUTE is greyed out A variable row is invalid (e.g. Min above Max, or no categorical choice checked), or there's nothing to sweep at all.
The run-count readout is red Above 5000 matches -- EXECUTE will ask you to confirm before starting. Reduce Points or Repetitions, or accept that it's going to take a while.
I pressed ABORT and it's still running Matches already in flight can't be interrupted -- ABORT stops new ones from starting, and the sweep finishes those already running before it reports done.
Everything's slow and the rest of the app stutters A sweep uses every CPU worker it's given. Turn Workers down, or run it when you don't need the machine for anything else.

08After a sweep: what next

A sweep answers score(design, strategy) for whichever strategies you checked -- but those strategies were written once, by a person, roughly with one robot in mind. A design that scores low might just be running a strategy nobody tuned for it. If a sweep result looks like a design is underperforming and you want to know its actual ceiling, that question belongs to the SEARCH tab -- it tunes a strategy's numbers specifically to the design you hand it, instead of judging every design by the same hand-written numbers.

09Glossary

Variable
One thing being swept: a target robot, a property on it, and the values to try.
Repetitions
How many times each point in the grid re-runs with a different seed. Needs variability on to mean anything -- see section 3.
Variability
Random perturbation of robot characteristics, start poses, and piece scatter, so repeated matches aren't identical.
Base seed
Where the sweep's randomness starts counting from. Fix it when comparing two designs so both see the same seeds.
Facet
Splits one plot into a grid of small plots, one per value of a third variable -- for when X and Y are already spoken for.
