The STRATEGY tab

A strategy is a robot's brain: a short list of rules -- if this is true, do that -- checked top to bottom, plus one fallback for when nothing else applies. This tab is where you read one, write one, and watch one think in real time.

No programming experience assumed. If a rule sounds like an "if" statement from a coding class, that's exactly what it is -- just built from dropdowns instead of typed out.

01The idea in one paragraph

Every tick, the robot looks at its rule list from the top down and runs the first one whose condition -- its trigger -- is currently true. That rule's tactic is what the robot actually does: drive somewhere, collect a piece, score, defend. If no rule's trigger is true, the robot falls back to the fallback tactic at the bottom, which every strategy has to have -- a robot has to do something every tick.

That's the entire model. A rule near the top of the list can interrupt one further down the moment its own trigger turns true -- which is what "priority" means here, and it's covered properly in section 5, because it's the part that surprises people.

04Editing does nothing until you do two things

Read this before you go looking for a bug

Editing a strategy here never touches a robot mid-match. There are two separate steps between "I changed something" and "the robot actually runs it":

1. APPLY TO ROBOT stages your edit -- it's saved in memory, attached to whichever robot the top bar says you're editing, but the robot on the field hasn't heard about it yet.
2. RESET, on the MATCH tab, is when a staged strategy actually replaces what the robot was running.

Skip either step and the field keeps running whatever it was running before. This is the same "nothing is live until RESET" rule the MATCH tab's own guide covers -- it's one rule, just visible from two different tabs.

05Priority: why order is the whole game

Drag a rule up the list and you've made it more important -- not "worth more points," but "checked first, and allowed to interrupt anything below it the instant its trigger turns true." A defend-when-threatened rule at the top of the list can cut off a collect-piece rule halfway through, every single tick, for as long as the threat trigger stays true.

A strategy with the same three rules in a different order is not a small variation on the same strategy -- it can be a completely different robot. When a strategy isn't doing what you expect, check order before you check anything else.

06Writing your first rule

Start from nothing

Pick a robot from the top bar, then New. You get zero rules and an Idle fallback -- a robot that does nothing, which is the correct starting point.

Add a rule

+ Rule adds one to the bottom of the list with a default trigger and tactic. Click it to open the inspector.

Trigger
the condition, e.g. "holding no coral"
Tactic
what to do, e.g. "go collect coral"

Make it real

Drag the rule to where its priority belongs, then APPLY TO ROBOT and RESET on MATCH to actually try it.

Every field in the inspector -- trigger type, tactic type, every numeric parameter -- is generated straight from that trigger or tactic's own declaration in the code. A new trigger type someone adds to the simulator shows up here with no changes to this editor at all; nothing about the form is hand-built per type.

07When something looks wrong

SymptomWhat is going on
I edited a strategy and the robot didn't change See "Editing does nothing until you do two things" above -- APPLY TO ROBOT, then RESET on MATCH.
The robot isn't doing what I expect Watch the STRATEGY GRAPH tab while the match runs. It shows exactly which rule is active and exactly which trigger fired to get there -- almost always faster than reading the rule list and guessing.
A rule never seems to fire Check whether a higher-priority rule's trigger is true first -- it will always win. Also check the trigger itself isn't stricter than intended (a for_duration requires the condition to stay true continuously for that long, not just briefly).
I switched robots and lost my edit You shouldn't have -- edits are kept in memory per robot when you switch the top-bar combo. If APPLY was never pressed for that robot though, the edit is still only staged, not saved to disk; Save As... writes it to a file if you want to keep it permanently.

08Glossary

Rule
One trigger + one tactic + a name and some timing (min duration, cooldown). The unit everything else here is built from.
Trigger
The condition that turns a rule on -- e.g. "holding a piece," "an opponent is within range." Can be combined (all of / any of / not) to build more specific conditions.
Tactic
What the robot does while a rule is active -- Collect, Score, Defend, Idle, or a scripted sequence.
Fallback
The tactic that runs when no rule's trigger is true. Every strategy has exactly one.
Priority
List order. Higher in the list wins, and can interrupt whatever a lower rule was doing. See section 5.
